# 中文长篇小说外部大脑与质量门禁设计

## 目标

在不依赖聊天窗口上下文的前提下，为中文长篇网络小说提供可恢复、可追溯、可增量执行的正文检查、长期记忆、上下文检索和发布门禁。系统只保存对后续剧情有价值的事实，并把所有正式事实追溯到章节正文位置。

## 方案

采用 Python 标准库实现的本地 CLI，数据以 Git 可审阅的 UTF-8 JSON/JSONL 文件保存。`book_inspect` 负责确定性检查和状态机；语言模型（ChatGPT、Codex、DeepSeek 等）只作为可选的事实抽取、局部润色和读者意见提供者，模型不可绕过最终门禁。

目录分为四层：`novel/` 保存用户正文与设定，`.book_inspect/memory/` 保存正式事实、关系历史、伏笔和快照，`.book_inspect/runs/` 保存可恢复的阶段检查点，`.book_inspect/reports/` 保存带输入哈希的证据报告。候选记忆先写入运行目录，终审通过后才提交正式记忆。

## 核心流程

1. 读取章节、设定和当前快照，按实体、关键词、世界规则、未解决线程、伏笔和最近章节筛选 Context Pack。
2. 对章节建立输入哈希并执行可复用阶段：统计、记忆候选、连续性、AI 症状、跨章重复、文风、读者模式。
3. 收集问题、证据位置和候选事实；修改只针对问题区段，修改后重新运行受影响阶段。
4. 最终门禁按硬规则阻止发布或给出警告。通过后原子地晋级正文版本、正式记忆和状态快照；失败只保留候选结果。
5. 任意阶段都写入 `runs/<run_id>.json`，重复执行按输入哈希复用，断线后从最后一个成功阶段继续。正式记忆以 `fact_id` 去重，关系和状态变化追加历史，不覆盖旧事实。

## 质量规则

硬阻止项包括有效字符低于配置下限、关键事实冲突、人物认知穿帮、时间线或世界硬规则冲突。AI 感检查使用频率、密度、窗口重复和结构异常生成证据，不输出虚假的“AI 概率”。文风档案描述可执行特征，不复制具体作者句子。读者模式只做可定位的阅读反馈。

## 可替换接口

`engine.py` 暴露纯 Python 函数和 `run_check()`；未来模型接入只需把模型结果转换为候选事实、问题和读者反馈 JSON，不改变存储、门禁、版本校验和恢复协议。

## 平台规则

`rules/platform_rules.json` 只登记公开官方入口、核验日期和可配置检查项，不写入未经官方证实的“AI 率阈值”或封禁传言。平台规则更新只修改该文件。

## 验收

内置 `demo` 和 `unittest` 场景覆盖：记忆抽取与筛选、无意义信息排除、关系历史、冲突检测、字数硬门禁、重复表达、对白风格、读者定位、失败不污染正式记忆、通过后更新快照、删除索引后恢复、断点续跑、幂等、输入变更失效、轻量恢复包和 100 章检索上限。
